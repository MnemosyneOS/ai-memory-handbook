# 附录 A：术语表

本表只收录在本书中被赋予特定含义的术语。通用工程词汇（如「接口」「部署」）不在此列。凡在正文中首次出现的英文术语，本表给出统一译法，全书不另立异名。

| 术语 | 英文 / 写法 | 定义 | 易混淆点 |
| --- | --- | --- | --- |
| 单遍 ADD-only | single-pass ADD-only | 写入时只追加新事实，一次模型调用完成，不修改或删除已有事实 | 与「只追加日志」不同：前者仍做结构化抽取与分型，后者只存原文 |
| 双时间轴 | dual time axis | 区分「事实何时发生」（`observation_date`）与「系统何时获知」（写入时间）两条时间线 | 与「版本链」不同：版本链记录同一实体的多次变更，双时间轴记录同一事实的两个时间维度 |
| 作用域 | scope | 记忆的隔离维度，本书特指 `user_id` / `agent_id` / `run_id` / `app_id` 四维 | 与「命名空间」不同：作用域是逻辑隔离维度，命名空间是物理承载单元 |
| 命名空间 | namespace | 由作用域派生出的独立存储单元，对应独立目录与独立数据库文件 | 不要把「配置写死的命名空间」当作「已隔离」 |
| 物理隔离 | physical isolation | 每个作用域一个独立文件，而非共享表加过滤条件 | 与「逻辑隔离」相对；后者的风险是遗漏过滤条件 |
| 哈希链审计账本 | hash-chained audit ledger | 每条记录包含前一条记录的 SHA-256 哈希，形成链式结构，篡改可被定位 | 与「操作日志」不同：日志可删可改不留痕，哈希链不能 |
| 来源追溯 | provenance tracing | 沿指针链从高层结论回溯到原始消息，回答「这个结论来自哪句话」 | 与「日志回溯」不同：后者回答「什么时候发生了什么」 |
| 指针链回溯 | pointer-chain backtracking | 沿 L3 → L2 → L1 的层级指针逐层取回内容与覆盖的消息 ID | 引擎不存 L0 原文，这是有意的隐私边界 |
| 渐进式披露 | progressive disclosure | 先返回目录（标题 + 一行摘要 + 展开成本），再按需展开正文的检索模式 | 与「分页」不同：前者按语义相关性决定展开，后者按位置切分 |
| 预算感知检索 | budget-aware retrieval | 在 token 预算约束下选择返回哪些记忆、以什么粒度返回 | 硬上限与软上限不同：硬上限按层丢弃，软上限可截断 |
| 无损压缩（AIC） | lossless compression | 把记忆压成「指针 + 结构化事实 + 内容原子」，数字、日期、金额、型号在任何层级完整保留，可字节级恢复 | 与「摘要压缩」不同：后者不可逆 |
| 内容原子 | content atom | 压缩后仍完整保留的关键事实片段，如数字、日期、金额、型号、URL、引号原话 | 原子在任何压缩层级都不被裁掉 |
| 级联删除 | cascade delete | 删除一条记忆时同步处理源记录、派生结论、检索缓存、依赖摘要四个层次 | 与「单条删除」不同：后者只处理第一层 |
| 掩码 | mask | 把正文替换为占位符但保留记录骨架，可撤销，不破坏 KV-Cache 前缀 | 与「删除」不同：存储中仍保留骨架，合规场景不可替代删除 |
| 公证 | notary | 写入前的安全检查管线：凭据检测与字段级脱敏、不可见 Unicode 检测、HTML 注入检测 | 与「检索时过滤」不同：前者让污染内容从未落地 |
| 敏感度分级 | sensitivity classification | 把内容分为 normal / private / secret 三级，据此决定写入准入与召回闸门 | 召回闸门默认开启且只拦 secret 级 |
| 冲突消解 | conflict resolution | 对新旧事实的矛盾做类型判定并选择动作（ADD / NOOP / UPDATE / KEEP_BOTH） | 六类判定：时间更新、偏好变更、作用域差异、精度差异、逻辑矛盾、来源冲突 |
| 相关性下限 | relevance floor | 低于该阈值的候选不进入结果集 | 与「top-k 截断」不同：前者可能返回少于 k 条甚至零条 |
| 词法回退 | lexical fallback | 嵌入服务不可用时，由 BM25 等词法信号提供基础召回 | 保证降级可用，但召回质量低于完整融合 |
| 睡眠时计算 | sleep-time compute | 后台进程在主流程空闲时整理与巩固记忆的架构思路 | 本书不对任何系统的当前实现下断言 |
| 七要素会话摘要 | seven-factor session summary | 会话摘要的固定结构：目标、约束、决策、未决、产物、失败、偏好，附逐字锚点 | 未决事项独立成条，不与摘要混存 |
| 前置条件三件套 | preconditions | 保存可复用经验时必填的 `must` / `must_not` / `typical_env` | 缺失前置条件的经验会在条件不匹配时造成负迁移 |
| 负迁移 | negative transfer | 在某场景有效的经验被无差别套用到不适用场景，造成事故 | 缓解手段是召回时做前置条件校验 |
| 黄金数据集 | golden dataset | 带输入、轨迹、结果与判据的高质量评估数据资产 | 与「测试集」不同：黄金数据集包含轨迹与判据，不只包含问答对 |
| 轨迹 | trajectory | 一次任务从目标到结果的完整执行记录，含工具调用与中间决策 | 与「Trace」不同：Trace 是观测记录，轨迹是可复用的行为证据 |
| 人在回路 | Human-in-the-loop，HITL | 关键步骤必须由人确认后才继续执行的架构原则 | 与「审批开关」不同：前者是架构原则，后者是功能点 |
| 检索增强生成 | Retrieval-Augmented Generation，RAG | 检索外部知识并注入上下文以生成回答 | 与「记忆检索」不同：前者的权威来自来源，后者的权威来自过程 |
| 受控自进化 | controlled self-evolution | 把有效经验转化为记忆、经验条目、工具与运行机制，并使其经评估与门禁后生效 | 与「自我修改」不同：前者必须经过可复现评估与可回滚发布 |
| 成熟度分级 | L1–L4 | 按「记忆承担的责任」与「可验证程度」两个轴划分的四级 | 自主度是与之正交的独立参数，不是分级依据 |
| 门控 | tier gate | 托管版按订阅层级收窄读取窗口的机制 | 默认关闭；自部署与 PyPI 用户不受限制 |

## A.1 关于术语的两点说明

**第一，「记忆」与「上下文」在本书中不是同义词。** 上下文是当前推理的输入，生命周期以一次调用为界；记忆是跨调用持久化的状态，生命周期以用户或任务的存续期为界。把二者混用会导致「上下文窗口变大就不需要记忆」这类推论。

**第二，「删除」在本书中始终指代四层语义之一，具体指哪一层由上下文决定。** 出现歧义时，本书会显式写出层级（标记删除、掩码、级联软删、物理删除）。读者在与供应商沟通时也建议采用同样的精确表述，因为「我们支持删除」这句话在合规语境下几乎不携带信息。
